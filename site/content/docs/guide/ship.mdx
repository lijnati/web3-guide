<Steps>
<Step>

### Point the frontend at Sepolia

After [deploying to Sepolia](/docs/guide/deploy#deploy-to-sepolia), update `web/.env.local`:

```bash title="web/.env.local"
NEXT_PUBLIC_CHAIN_ID=11155111
NEXT_PUBLIC_CONTRACT_ADDRESS=0x…your Sepolia address…
NEXT_PUBLIC_SEPOLIA_RPC_URL=https://eth-sepolia.g.alchemy.com/v2/<key>
```

Restart `npm run dev`, switch MetaMask to Sepolia, and run through every state once on the real network.

<Callout title="Is an RPC key in NEXT_PUBLIC safe?">
  Anyone who opens your site can see it. A free-tier key is acceptable for a demo or prototype. For anything long-lived, restrict the key to your domain in the provider's dashboard, or leave the variable empty to use the public RPC.
</Callout>

</Step>
<Step>

### Build locally

```bash
npm run lint
npm run build
```

**Expected:** `✓ Compiled successfully`, then a route table. Fix errors here, where builds take seconds, rather than on Vercel.

**If it fails:**
- A type error on `functionName` or `args` → the ABI is stale. Run the export script again.
- `Module not found: @/lib/myContractAbi` → the ABI file was never generated. It's generated but must be **committed**.

</Step>
<Step>

### Push to GitHub

```bash
git status   # .env.local must NOT be listed
git add .
git commit -m "My dApp"
git push
```

Commit `contracts/ignition/deployments/` and `web/lib/*Abi.ts`. Never commit `.env.local` or a private key.

</Step>
<Step>

### Deploy to Vercel

1. At [vercel.com/new](https://vercel.com/new), import the repository.
2. Set **Root Directory** to `web`. This is easy to miss, and the build fails without it.
3. Add the environment variables from `.env.local`: `NEXT_PUBLIC_CHAIN_ID`, `NEXT_PUBLIC_CONTRACT_ADDRESS` and, optionally, `NEXT_PUBLIC_SEPOLIA_RPC_URL`.
4. Click **Deploy**.

**Expected:** a `https://<project>.vercel.app` URL where reads load even without a wallet.

`NEXT_PUBLIC_*` values are baked in **at build time**. After editing them in Vercel, go to *Deployments → ⋯ → Redeploy*.

</Step>
</Steps>

## Launch checklist

- [ ] All contract tests pass
- [ ] Contract deployed to Sepolia and visible on Etherscan
- [ ] ABI exported **after** the last contract change
- [ ] Frontend env vars point to the **current** Sepolia address and chain `11155111`
- [ ] `npm run build` passes locally
- [ ] Vercel: Root Directory `web`, env vars set, redeployed after changes
- [ ] The live URL loads data in a private window with no wallet
- [ ] A full write round-trip works on the live site with MetaMask
- [ ] No private keys in Git history

## Where to go next

- **Verify your contract** on Etherscan so others can read the source. Hardhat's `ignition deploy` accepts a `--verify` flag once an Etherscan API key is configured; see the verification guide in the [Hardhat docs](https://hardhat.org/docs).
- **Use audited building blocks** for tokens, NFTs and access control: [OpenZeppelin Contracts](https://docs.openzeppelin.com/contracts).
- **Go deeper** in the official docs: [Hardhat](https://hardhat.org/docs), [wagmi](https://wagmi.sh), [viem](https://viem.sh), [Next.js](https://nextjs.org/docs).
