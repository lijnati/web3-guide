A dApp is cheap to change in the frontend and expensive to change in the contract. Ten minutes of planning saves redeploys.

## What goes on-chain?

Put something on-chain only if it needs to be **public, tamper-proof, or owned by users**. Everything else stays in the frontend or a normal backend.

| Good on-chain | Keep off-chain |
| --- | --- |
| Balances, ownership, votes, payments | Images, videos, long text (store a link or hash instead) |
| Rules everyone must trust ("only the owner can…", "max 100 per wallet") | Search, sorting, filtering, analytics |
| Records that must be permanent and public | Private data: on-chain data is **public to everyone** |
| Small values: numbers, addresses, short strings | Anything that changes many times a second |

<Callout type="warn" title="Nothing on-chain is private">
  `private` in Solidity only stops other *contracts* from reading a variable. Anyone can still read it straight from the chain. Never store secrets, passwords or personal data.
</Callout>

## Design the interface first

Before writing Solidity, list your contract's functions the way you would design a REST API:

| Kind | Solidity | Costs gas? | Needs wallet? | Example |
| --- | --- | --- | --- | --- |
| Read | `view` / `pure` function, `public` variable | No | No | `value()`, `balanceOf(address)` |
| Write | normal `external` function | Yes | Yes | `setValue(uint256)`, `vote(uint256)` |
| Payable write | `external payable` | Yes + ETH sent | Yes | `buy()`, `donate()` |
| Event | `event` + `emit` | Part of a write | — | `ValueChanged(by, newValue)` |
| Error | `error` + `revert` | — | — | `ZeroValue()`, `NotOwner()` |

Also decide:

- **Who may call each write?** Anyone, only the owner, or only some addresses.
- **What should revert?** Each rule becomes a custom error and a test.
- **What does the constructor need?** Initial values, an owner, token names and so on.

## How the pieces connect

```text
 contracts/MyContract.sol ──build──▶ ABI ──export──▶ web/lib/myContractAbi.ts ─┐
            │                                                                   ├──▶ wagmi hooks
            └──deploy──▶ contract address ──▶ web/.env.local ───────────────────┘
```

The frontend needs exactly two facts about your contract: its **ABI** (which functions exist) and its **address** (where it lives). If either is out of date, nothing works. Each time you change the contract, export the ABI again and update the address.
