## The big idea

A dApp is a normal website whose **backend is a smart contract**. Anyone can read it. Anyone can use it. But every change costs a small fee, and the user must approve it with their wallet.

| You know (Web2) | In Web3 | What's different |
| --- | --- | --- |
| Backend + database | **Smart contract** | Lives on the blockchain. Can't be edited after deploy. |
| Login | **Wallet** (MetaMask) | Users sign with a key. No passwords. |
| User ID | **Address** (`0x5FbD…0aa3`) | The user's public ID |
| `GET` request | **Read** | Free and instant. No wallet needed. |
| `POST` request | **Write** (transaction) | Costs a fee, needs the wallet, takes a few seconds |
| API docs | **ABI** | A list of the contract's functions |
| Server URL | **Contract address** + **RPC URL** | The address says *which* contract. The RPC is the server you talk to. |
| Staging | **Testnet** (Sepolia) | A real network with free test money |
| Server logs | **Events** + Etherscan | Public records of what happened |
| Database migration | **Redeploy** | To fix a contract, you deploy a new one at a new address |

## Words you'll see

- **Gas:** the fee for a write, paid in ETH. On Sepolia you use free test ETH.
- **Chain ID:** the number of a network. Sepolia is `11155111`. Your local test chain is `31337`.
- **RPC URL:** the web address of a server that talks to the blockchain. Alchemy and Infura give you one for free.
- **Transaction hash:** the tracking number of a write. You get it right away, but the write isn't done yet.
- **Receipt:** proof the write is done. It says if it worked or **reverted**.
- **Revert:** the contract said no (like HTTP 400). Nothing changes, but the fee is still paid.

## What happens when a user writes

Your website should show each step:

```text
 user clicks "Save"
        │
        ▼
 1. wallet popup opens ........ "Confirm in wallet…"     (user can say no)
        │ user approves
        ▼
 2. you get a hash ............ "Waiting for a block…"   (link to Etherscan)
        │ about 12 seconds on Sepolia
        ▼
 3. receipt arrives ........... "Done!" or "Failed: <reason>"
        │
        ▼
 4. read the data again ....... the new value shows up
```

A common mistake is treating step 2 as "done". [Read & write](/docs/guide/read-write) shows how to handle every step.

<Callout type="warn" title="A private key is a password you can never change">
  Anyone with your private key owns your wallet. Use a **separate MetaMask account with no real money** for development. Never put a key in Git or in a `NEXT_PUBLIC_*` variable.
</Callout>
