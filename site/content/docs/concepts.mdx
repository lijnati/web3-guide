## The mental model

A dApp is a normal web app whose **backend is a smart contract**. Anyone can read that backend, and anyone can call it, but every change costs a small fee and must be signed by the user.

| You know (Web2) | Web3 equivalent | What changes |
| --- | --- | --- |
| Backend API + database | **Smart contract** | Code and data live on the blockchain. Deployed code cannot be edited. |
| User login | **Wallet** (MetaMask) | The user proves identity by signing with a private key. No passwords. |
| User ID | **Address** (`0x5FbD…0aa3`) | A 20-byte public identifier, derived from the key. |
| `GET` request | **Read** (`view` function) | Free, instant, needs no wallet. |
| `POST` request | **Write** (transaction) | Costs gas, needs a wallet signature, takes seconds to confirm. |
| API docs / OpenAPI | **ABI** | JSON that describes the contract's functions, so the frontend can call them. |
| Server URL | **Contract address** + **RPC URL** | The address says *which* contract; the RPC is the server you talk to. |
| Staging environment | **Testnet** (Sepolia) | A real network with free, worthless ETH. |
| Server logs | **Events** + block explorer (Etherscan) | Public, permanent records of what happened. |
| Database migration | **Redeploy** | You can't change a deployed contract. A fix means a new contract at a new address. |

## The words you will see

- **Gas:** the fee paid for a write, in ETH. On Sepolia it is paid in free test ETH from a faucet.
- **Chain ID:** the number that identifies a network. Sepolia is `11155111`. A local Hardhat node is `31337`. Wallets use it to stop you sending a transaction to the wrong network.
- **RPC URL:** an HTTPS endpoint that speaks Ethereum JSON-RPC. Alchemy, Infura and public nodes all provide them.
- **Transaction hash:** the "tracking number" of a write. Your wallet returns it immediately; the transaction is *not done yet* at that point.
- **Receipt:** proof that the transaction was mined into a block. It says whether the transaction succeeded or **reverted**.
- **Revert:** the contract refused the call (like an HTTP 400). All its changes are undone, but the gas is still spent.

## The lifecycle of a write

This is the flow your UI has to show, step by step:

```text
 user clicks "Sign"
        │
        ▼
 1. wallet popup opens ........ UI: "Confirm in wallet…"     (user can reject)
        │ user approves
        ▼
 2. tx hash returned .......... UI: "Waiting for a block…"   (link to Etherscan)
        │ ~12 s on Sepolia
        ▼
 3. receipt arrives ........... UI: "Success!" or "Reverted: <reason>"
        │
        ▼
 4. re-read contract data ..... UI: new entry appears
```

Most beginner bugs come from treating step 2 as "done". [Read & write](/docs/guide/read-write) shows how to handle every step.

<Callout type="warn" title="Private keys are passwords you can never reset">
  Anyone who has your private key controls the wallet. Use a **separate MetaMask account with no real funds** for development, and never commit a key to Git or put it in a `NEXT_PUBLIC_*` variable.
</Callout>
